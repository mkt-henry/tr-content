# 멀티 에이전트 추론 — 오케스트레이터 협업 영상 개선 설계

- 날짜: 2026-06-22
- 대상: `src/demos/alphalenz/multi-agent/`
- 목적: 알파렌즈 "멀티 에이전트 추론" 데모 영상의 (1) 오케스트레이터 작동 모션 고급화,
  (2) 각 에이전트가 무엇을 사고하고 어떤 데이터를 처리하는지 가시화,
  (3) 전반적 UI 전문성 향상.

## 문제 정의 (현재 상태)

현재 데모는 `idle → routing → working → verifying → done` 단계를 거치며,
좌측 노드 그래프(Orchestrator 1 + 5 그룹 + 16 서브 에이전트)와 우측 320px 패널
(48 카운터 / 7줄 로그 / 인사이트 카드)로 구성된다.

한계:
1. **모션이 단조롭다.** 엣지 `pathLength` 펄스 + dash 흐름 + 노드 스피너/체크가 전부라
   "데이터가 실제로 흐르고 처리되는" 감각이 없다.
2. **에이전트의 사고/데이터가 안 보인다.** 노드에는 라벨만 있고, 각 에이전트가 *무엇을
   생각하고 어떤 데이터를 다루는지*는 우측 7줄 로그로만 추상적으로 표현된다.
3. **전문성 부족.** 데이터 밀도와 모션 디테일이 첨단 AI 제품 수준에 못 미친다.

## 설계 방향

**카메라 포커스(클로즈업) 모델**: 그래프는 전체 협업 흐름을 유지하고, 진행 단계가 흐르면서
"지금 일하는" 에이전트를 우측 확대 패널에 **카메라처럼 클로즈업**한다. 그 에이전트의
사고 과정·데이터 소스·중간 산출물·근거를 펼쳐 보여준다.

**레이아웃**: `좌측 에이전트 그래프(전체 흐름) + 우측 ~440px 포커스 패널`.
기존 카운터/로그는 포커스 패널 안으로 흡수한다.

## 섹션 1 — 좌측 그래프 모션 업그레이드 (`AgentGraph.tsx`)

기존 펄스/dash/스피너를 다음으로 교체·보강한다.

1. **데이터 패킷 입자** — 엣지(베지어 곡선)를 따라 작은 발광 입자가 실제로 이동.
   Orchestrator→그룹→서브로 데이터가 흘러가는 물리적 감각. framer-motion `offsetPath`
   또는 곡선 좌표 보간으로 구현.
2. **노드 점등 리플 + 호흡 글로우** — 활성화 순간 파동(ripple)이 퍼지고, 처리 중엔 글로우가
   호흡하듯 펄스 + 미세 프로그레스 링.
3. **카메라 피사계 심도(핵심 차별점)** — 우측에서 클로즈업 중인 에이전트는 그래프에서
   **링 하이라이트 + 확대**, 나머지 노드는 **디밍/블러**. 카메라가 이 노드를 보고 있다는
   시선 유도.
4. **단계별 시그니처 모션**:
   - `routing`: Orchestrator가 질문을 토큰 조각으로 쪼개 5개 그룹으로 흩뿌리는 분해 모션
   - `working`: 그룹별 병렬 점등 + 입자 흐름
   - `verifying`: 그룹 간 크로스 검증 라인을 양방향 입자로
   - `done`: 모든 결과가 Orchestrator로 역류·수렴하며 합성 플래시

## 섹션 2 — 우측 포커스 패널 (신규 컴포넌트 `FocusPanel.tsx`)

클로즈업되는 에이전트 1명당 위→아래로 4요소:

```
┌─ 포커스 ─────────────────┐
│ 🔵 펀더멘털 › 재무제표         │  헤더: 그룹색 + 에이전트명 + 상태칩
│ "24Q3 영업이익 추세를 확인…"  │  ① thinking 토큰 스트림(타이핑)
│ ┌ tool ─────────────┐    │
│ │ ▸ retrieve_filings(24Q3)│  ② tool call / 데이터 소스 (실행→완료)
│ │ ▸ fetch_consensus()    │
│ └────────────────────┘    │
│ ┌ 산출물 ┐ PER 11.2x ↓     │  ③ 중간 산출물 미니 시각화
│ │ ▁▃▅▇▆ │ 시그널: 우호       │     (미니 스파크라인 + 메트릭 + 태그)
│ └───────┘                 │
│ 근거 ▸ DART 24Q3 · 컨센서스 ·│  ④ 근거 체인 (출처 칩 + 교차확인 N건)
│      ✓ 3개 소스 교차확인      │
└──────────────────────────┘
```

- **① thinking 토큰 스트림**: 추론 문장이 한 글자씩 타이핑되듯 스트리밍. focus 변경 시 재생.
- **② tool call / 데이터 소스**: 함수호출 형태 라벨(`retrieve_filings(24Q3)` 등)이
  실행→완료로 점등.
- **③ 중간 산출물 미니 시각화**: 미니 스파크라인 + 메트릭 값(PER 11.2x 등) + 시그널 태그
  (과열/중립/우호).
- **④ 근거 체인**: 출처 칩 + "N개 소스 교차확인" 검증 표시.

routing/verifying/synthesis 단계에서는 단일 에이전트 대신 **Orchestrator 요약 뷰**
(분해/검증/합성 메시지)를 같은 패널에 표시한다.

## 섹션 3 — 데이터 모델 (`data.ts`)

그룹당 **대표 에이전트 1개씩(총 5개)** 에 대해 클로즈업 스크립트를 추가한다. 16개 전부가
아니라 대표 장면만 작성한다(8.6초→14초 영상에 16개 클로즈업은 무리).

에이전트별 스크립트 타입(개념):

```ts
interface FocusScript {
  groupId: string;
  subIndex: number;          // 그룹 내 대표 에이전트
  thinking: L<string>;       // 추론 문장 1~2개 (한/영)
  tools: string[];           // 함수호출 라벨 2~3개
  metric: { label: string; value: string; trend: 'up'|'down'|'flat' };
  signal: L<string>;         // 시그널 태그 (우호/과열/중립…)
  spark: number[];           // 스파크라인용 숫자 배열
  evidence: { sources: L<string>[]; crossChecks: number };
}
```

`thinking`/`signal`/`evidence.sources`는 한·영(`L`) 모두 작성. 나머지(tool 라벨, 메트릭,
스파크 배열)는 언어 무관.

## 섹션 4 — 상태머신 · 타이밍 (`state.ts` / `scenario.ts`)

**상태 추가**:
- `focus: FocusTarget | null`
  - `FocusTarget = { groupId: string; subIndex: number } | 'routing' | 'verifying' | 'synthesis'`
- 그래프 하이라이트와 포커스 패널이 `focus`를 공유. thinking 타이핑은 패널 내부에서
  focus 변경 시 재생(별도 전역 상태 불필요).

**타이밍 흐름**:
- `routing` (~2s): 분해 모션 + 패널은 "5개 도메인으로 분해" 요약 (`focus='routing'`)
- `working` (~7.5s): 그룹 순회, 그룹당 대표 에이전트를 **약 1.4초씩 클로즈업**
  (5 × 1.4 ≈ 7s). 그래프는 그룹 전체 병렬 점등, 카메라는 대표 1명.
- `verifying` (~2s): 크로스 검증 양방향 입자 + 패널 "상충 신호 1건 → 해소"
  (`focus='verifying'`)
- `done`: 수렴 플래시 + 인사이트 카드 (`focus='synthesis'` 후 카드)

전체 길이 8.6초 → **약 13~14초**. `scenario.ts`의 `wait` 값을 이에 맞춰 조정.

## 섹션 5 — 모바일 + variant

- **모바일(`Mobile.tsx`)**: 가로로 패널을 둘 공간이 없으므로 그래프(상단 축소) 아래
  **포커스 패널을 세로 스택**. 클로즈업 시퀀스는 동일 재생, 미니 시각화/근거 칩은 1열.
- **variant**:
  - `orchestrate`(v1, 분석 품질): thinking·근거 체인 강조.
  - `parallel`(v2, 처리 규모): 동일 패널, 클로즈업을 더 빠르게 스킵하며 48 카운터·병렬성
    로그(`LOGS_PARALLEL`) 강조.
- 색/테마는 기존 `AL` 테마·퍼플 액센트 유지. 전문성은 모션·데이터 밀도로 확보.

## 컴포넌트 경계

- `AgentGraph.tsx` — 그래프 렌더 + 모션. `focus`를 읽어 피사계 심도 적용. 입자/리플/단계
  모션 담당.
- `FocusPanel.tsx` (신규) — `focus`와 `FocusScript`를 읽어 4요소 클로즈업 렌더. thinking
  타이핑 자체 관리.
- `data.ts` — `GROUPS` + 신규 `FOCUS_SCRIPTS` + 기존 로그/인사이트.
- `state.ts` — `focus` 추가, working 루프를 포커스 시퀀스로 재구성.
- `scenario.ts` — wait 타이밍 재조정.
- `Desktop.tsx` / `Mobile.tsx` — 레이아웃 재배치(좌 그래프 / 우 440px 패널 · 모바일 세로 스택).

## 테스트 / 검증

- 타입 체크 및 빌드 통과.
- dev 서버에서 두 variant 재생 확인: routing→working(5 클로즈업)→verifying→done 흐름,
  thinking 타이핑·tool 점등·스파크라인·근거 칩이 단계와 맞물리는지.
- 카메라 포커스 시 활성 노드 하이라이트 + 나머지 디밍이 동작하는지.
- 모바일 레이아웃에서 세로 스택이 깨지지 않는지.

## 비범위 (YAGNI)

- 16개 에이전트 전부의 클로즈업 스크립트 (대표 5개만).
- 실제 LLM 호출/실데이터 연동 (데모용 스크립트 고정).
- 색 팔레트/테마 전면 개편 (기존 유지).
